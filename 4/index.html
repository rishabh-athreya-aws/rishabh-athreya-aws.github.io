A.1 · Shoot the pictures

I use three sequences of six overlapping photographs: an apartment interior, the exterior of Wheeler, and the interior of Gateway. Each sequence sweeps across the scene. The intended model is camera rotation about a fixed center of projection, so overlapping views can be related by a homography. In practice, nearby objects and people make the indoor scenes less forgiving of small viewpoint changes.

The processing pipeline corrects image orientation, converts to RGB, and resizes each frame to 750 × 1000. The grids below show all six working images in their numbered order; these same frames form the mosaics in A.4.

A.2 · Recover homographies

I manually specify matching landmarks for each neighboring pair: 1 → 2, 2 → 3, 3 → 4, 4 → 5, and 5 → 6. Each pair uses 8–14 correspondences, giving more constraints than the minimum of four. The function computeH(im1_pts, im2_pts) estimates the transformation from the first image’s coordinates to the second image’s coordinates.

From point matches to a linear system

For a source point (x, y) and destination point (u, v), the homogeneous mapping is p′ ∼ Hp. Fixing h₃₃ = 1 leaves eight unknowns. Dividing by the homogeneous scale gives:

u = (h₁₁x + h₁₂y + h₁₃) / (h₃₁x + h₃₂y + 1)
v = (h₂₁x + h₂₂y + h₂₃) / (h₃₁x + h₃₂y + 1)

Rearranging gives two rows per point pair. Stacking N pairs produces a 2N × 8 system A h = b:

[ x  y  1  0  0  0  −ux  −uy ] h = u
[ 0  0  0  x  y  1  −vx  −vy ] h = v

h = [h₁₁ h₁₂ h₁₃ h₂₁ h₂₂ h₂₃ h₃₁ h₃₂]ᵀ

Before solving, I center each point set and scale it so the mean distance from its center is √2. I solve the normalized system with least squares, then recover the original coordinate mapping as H = T₂⁻¹ Hₙ T₁ and normalize the bottom-right entry to 1. This improves numerical conditioning when coordinate products are much larger than the constant terms.

A.3 · Warp and rectify

I implement warpImageNearestNeighbor(im, H) and warpImageBilinear(im, H) using inverse warping. For each output pixel, I apply H⁻¹ and divide by the resulting homogeneous coordinate to find a floating-point source location. Sampling this way fills the destination grid without the holes that forward placement can leave.

For an unrestricted warp, the transformed image corners determine the output bounds. A separate validity mask records whether each mapped location lies inside the source. This preserves genuinely black image pixels while keeping uncovered areas transparent. For rectification, I instead specify the output rectangle directly.

Two interpolation methods

Nearest neighbor rounds each valid coordinate to the closest source pixel. Bilinear interpolation combines the four surrounding pixels according to the fractional horizontal and vertical offsets. Both are implemented directly in NumPy.

I(x, y) = (1 − α)(1 − β) I₀₀ + α(1 − β) I₁₀
+ (1 − α)β I₀₁ + αβ I₁₁

Here α = x − ⌊x⌋ and β = y − ⌊y⌋. Neighbor indices are clamped at the image boundary.

Quality and runtime

The laptop display exposes the sampling trade-off in small text and thin lines: nearest neighbor retains harder pixel transitions, while bilinear interpolation blends them into a softer result. The window rectification similarly lets me compare the diagonal building edges. At page size the difference is subtle; the full-size outputs make it easier to inspect. Neither method can recover detail absent from the source photograph.

A.4 · Blend the images into a mosaic

Each panorama uses all six frames from its source sequence. I first compose the adjacent homographies into image 3’s coordinate system. Images 1 and 2 use forward compositions; images 4–6 use inverse adjacent transformations. For example, H₁→₃ = H₂→₃ H₁→₂ and H₄→₃ = H₃→₄⁻¹.

Choose a common canvas

I apply one additional projective transform to the entire scene, centered at (375, 500), to reduce extreme canvas stretching. Its two perspective parameters are selected separately for each scene. This is still a planar projective mosaic, not a cylindrical or spherical projection.

C = [1 0 −375; 0 1 −500; 0 0 1]
P = C⁻¹ [1 0 0; 0 1 0; a b 1] C

Apartment: (a, b) = ( 0.00012,  0.00000)
Wheeler:   (a, b) = (−0.00010, −0.00005)
Gateway:   (a, b) = (−0.00025, −0.00012)

The union of the transformed corner bounds defines the canvas. A common scale brings its longer side to approximately 3000 pixels. Each resized source frame is inverse-warped directly into that final canvas, so the process avoids repeatedly resampling an intermediate mosaic.

Feather the overlaps

I assign each source pixel a positive weight based on its distance to the closest image edge, normalized by the largest weight in that image. A one-pixel floor keeps boundary weights nonzero. The color image and its weight map are warped with the same homography, then the validity mask removes samples outside the source.

M(p) = Σᵢ wᵢ(p) Iᵢ(p) / Σᵢ wᵢ(p)

Where images overlap, their contributions change gradually. Where only one image contributes, normalization preserves its color. Pixels with no coverage remain transparent. Feathering softens seams; it cannot correct a misplaced edge or a moving subject.

Observations and limitations

Rectification provides a direct check of the homography and inverse-warping implementation: a selected quadrilateral becomes the requested rectangle. The interpolation comparison then separates geometry from sampling quality.

Mosaicing introduces a different challenge. Small pairwise errors accumulate through the six-frame chain, and a single homography cannot align every depth plane if the camera translates. The full, uncropped results make both the shared coverage and the strong outer-frame stretching visible. More accurate stationary landmarks and a more stable capture position would improve alignment; a different projection would address the appearance of very wide views.

This report covers A.1–A.4. No spherical, cylindrical, or polar-mapping extension is included for A.5.
